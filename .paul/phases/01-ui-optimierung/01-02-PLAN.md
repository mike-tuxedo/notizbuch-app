<objective>
## Goal
PWA-Install im Standalone-Modus auf Android (Chrome) zum Laufen bringen, durch Ergänzen der von Chrome geforderten 192×192 und 512×512 PNG-Icons im Manifest. Service-Worker-Cache aktualisieren, sodass Bestandsinstallationen das neue Manifest sehen.

## Purpose
Aus dem Deferred Issue von 01-01: PWA startet auf Android mit Browser-Controls statt Standalone. Chrome verlangt für Installierbarkeit explizit ein `192×192` und `512×512` Icon im Manifest — `apple-touch-icon-*` (180×180) zählt nur für iOS. Ohne diese Icons fehlt die Standalone-Erfahrung, was Daily-Driver-Readiness auf Android blockiert.

## Output
- Zwei neue Icon-Dateien: `img/icon-192.png`, `img/icon-512.png`
- `manifest.json` referenziert beide neuen Icons (mindestens eines davon `purpose: "any maskable"`)
- `sw.js` `CACHE_NAME` v42 → v43, neue Icons in `STATIC_ASSETS` registriert
- `.paul/phases/01-ui-optimierung/01-02-SUMMARY.md` nach UNIFY
</objective>

<task type="auto">
  <name>Task 1: Icons generieren (192×192, 512×512) aus 180er-Source</name>
  <files>img/icon-192.png, img/icon-512.png</files>
  <action>
    1. Source-Icon: `img/apple-touch-icon-180x180.png` (180×180, größtes vorhandenes PNG, RGBA).
    2. ImageMagick verwenden (verfügbar: `magick` und `convert`):
       - Für 192×192:
         `magick img/apple-touch-icon-180x180.png -filter Lanczos -resize 192x192 img/icon-192.png`
         180→192 ist nur ~6.7% Upscale — visuell unkritisch.
       - Für 512×512:
         `magick img/apple-touch-icon-180x180.png -filter Lanczos -resize 512x512 img/icon-512.png`
         180→512 ist ~2.84× Upscale — leicht weicher als nativ. Akzeptabel als Übergang; im SUMMARY als Hinweis dokumentieren, dass eine native Hi-Res-Quelle später ersetzt werden kann.
    3. Verifikation per `file img/icon-192.png` und `file img/icon-512.png`: Output muss "PNG image data" mit korrekter Dimension enthalten.

    Avoid:
    - SVG generieren statt PNG (Manifest spricht hier "type":"image/png" an, nicht zwingend nötig aber konsistent mit Bestand).
    - Quadrat erzwingen wenn die Source-Datei keine ist (180er ist quadratisch ✓).
  </action>
  <verify>
    `file img/icon-192.png` zeigt "PNG image data, 192 x 192" und `file img/icon-512.png` zeigt "PNG image data, 512 x 512".
  </verify>
  <done>AC-1 erfüllt.</done>
</task>

<task type="auto">
  <name>Task 2: manifest.json + sw.js aktualisieren</name>
  <files>manifest.json, sw.js</files>
  <action>
    1. `manifest.json` icons-Array erweitern:
       - Hinten anhängen:
         ```json
         { "src": "img/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any maskable" },
         { "src": "img/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" }
         ```
       - Bestehende Icons unverändert lassen — apple-touch-icon-* werden weiter für iOS gebraucht.
       - JSON valide halten (Komma-Logik beachten).

    2. `sw.js`:
       - `CACHE_NAME` von `'notizbuch-v42'` → `'notizbuch-v43'` anheben.
       - Falls in `STATIC_ASSETS` andere `img/`-Pfade gelistet sind: `img/icon-192.png` und `img/icon-512.png` ergänzen.
       - Falls `STATIC_ASSETS` nur HTML/JS/CSS listet (Icons werden lazy gefetched), Icons NICHT zwingend ergänzen, aber dokumentieren.

    Avoid:
    - Andere Manifest-Felder anfassen (display, start_url, scope, theme_color etc.).
    - Andere SW-Strategien ändern.
  </action>
  <verify>
    - `python3 -c "import json; json.load(open('manifest.json'))"` (oder `node -e "JSON.parse(require('fs').readFileSync('manifest.json'))"`) wirft keinen Fehler.
    - `grep -n "icon-192\|icon-512" manifest.json` zeigt zwei Einträge.
    - `grep -n "CACHE_NAME" sw.js` zeigt 'notizbuch-v43'.
  </verify>
  <done>AC-2 + AC-3 erfüllt.</done>
</task>
